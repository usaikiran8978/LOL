# Requirements Traceability Matrix

Every requirement from the BRD, the Technical Document (TECH) and the master development prompt (MP) is tracked here.
Nothing is complete until its row reaches **DONE** under the Definition of Done (BRD §24 / TECH §23 / MP §39).

Last full audit: **2026-10-09**, after phases P1–P12. Every row was checked against the code and test sources (see the Summary at the end).
The test suites were **not executed** during this audit (other engineers were working in the apps). A test listed below exists in the
source; it is not a claim that it passed on the audit date.

**Status legend**

| Status | Meaning |
|---|---|
| `DONE` | API + DB + validation + authZ + automated tests exist, **and** the client UI exists where the requirement is user- or admin-facing (mobile screen for member features, admin console page for admin-controlled config). Server-only requirements (outbox, jobs, rate limiting, …) are DONE without UI. A short note after DONE records a minor caveat that does not block the requirement. |
| `PARTIAL` | Something real is missing. The Status cell says exactly what. |
| `BE` | Backend (API + DB + validation + authZ + automated tests) done; the client UI is missing. |
| `NOT DONE` | Not implemented. The Status cell says why. |

**Column abbreviations:** Scr = mobile route under `apps/mobile/app/` (`M:`) / admin route under `apps/admin/src/app/(console)/` (`A:`);
Tables = PostgreSQL tables (see `apps/api/migrations`); AE = analytics event; Sec = security/privacy requirement.
API routes are shown with their `/v1` prefix (only `/health/*` and `/metrics` are unprefixed).

**Test notation:** `e2e:<name>` = `apps/api/test/<name>.e2e-spec.ts` · `unit:<name>` = `apps/api/src/**/<name>.spec.ts` or `packages/shared/src/<name>.spec.ts` ·
`mt:<name>` = `apps/mobile/src/**/__tests__/<name>.test.tsx` or `apps/mobile/src/<dir>/<name>.test.ts` · `at:<name>` = `apps/admin/src/**/<name>.test.ts(x)`.
Quoted text is the start of the real test title; `(n)` = number of tests in that `describe`/file for the feature.

Phase numbers follow MP §36 / TECH §24 delivery order: P1 foundation/auth · P2 profile/onboarding · P3 questionnaire engine · P4 matching · P5 discovery · P6 chat · P7 safety/verification · P8 subscriptions · P9 AI · P10 events/dates · P11 analytics/experiments · P12 hardening.
